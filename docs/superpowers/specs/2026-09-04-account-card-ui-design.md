# 账号列表卡片化 UI 设计

## 目标

把平台管理页的账号列表从横向数据表改为“一账号一张卡片”，让运营人员在桌面和手机上都能先看到身份、状态、额度和下一步操作。图二只作为信息层级参考，所有字段都从本系统现有账号响应、探测快照、额度账本和同步状态读取。

## 范围与边界

- 只修改 `frontend` 的呈现层，不新增后端接口，不写入或重启 Codex2API。
- 保留现有搜索、状态/时间筛选、分页、选择、批量操作、详情、接码、删除和平台动作。
- 对密码、Refresh Token 和邮箱使用默认隐藏/截断展示，复制操作仍然保留。
- 数据缺失时显示明确的“尚无数据”状态，不生成模拟额度、价格或有效期。

## 卡片结构

1. 顶部：选择框、脱敏邮箱、账号状态、套餐、HTTP 状态、同步和重置标记。
2. 身份区：工作区、当前目标、号池、登录方式、用户 ID、同步记录数量。
3. 异常区：把本地探测的认证/Codex 错误以可读提示呈现，并提供详情入口。
4. 凭据区：密码和 Refresh Token 的隐藏预览与复制按钮；可选备注单独显示。
5. 额度区：7 天窗口的剩余百分比、重置时间、请求数、流量、已计费金额和剩余估算。没有账本时回退到本地 Codex 探测 payload 的窗口百分比。
6. 商务区（有数据才显示）：有效期、实际价格、倍率和最近检查时间。
7. 底部：创建时间与详情、接码、试用链接、删除及平台动作。

## 布局与响应式

- 使用语义化表格行承载卡片，以保留键盘/辅助技术的记录边界；视觉层将 `tbody` 转为 CSS Grid。
- `auto-fit` 网格在宽屏展示多列，680px 以下切为单列；工具栏和分页在窄屏换行。
- 使用主题 token 注入 CSS 自定义属性，兼容现有暗色/亮色主题；交互保留可见焦点和 180ms 状态过渡，并尊重减少动效设置。

## 验证

- `AccountCard.test.tsx` 覆盖身份、套餐、额度、缺失数据、选择和复制行为。
- 现有 `Accounts.test.tsx` 保持 34 个回归断言通过。
- 发布前运行前端全量测试、ESLint、TypeScript/Vite 生产构建，并在浏览器中检查桌面与 390px 移动视口。
