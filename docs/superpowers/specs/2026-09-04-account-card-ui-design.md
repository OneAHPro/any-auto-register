# 账号列表卡片化 UI 设计

## 目标

把平台管理页的账号列表从横向数据表改为“一账号一张卡片”，让运营人员在桌面和手机上都能先看到身份、状态、额度和下一步操作。图二只作为信息层级参考，所有字段都从本系统账号响应和只读的 Codex2API 账号摘要读取；Codex2API 本身不做任何写入。

## 范围与边界

- 账号列表增加一个显式的 `include_live` 只读投影参数，仅在 ChatGPT 列表请求中读取已配置目标的账号摘要；不写入或重启 Codex2API。
- 保留现有搜索、状态/时间筛选、分页、选择、批量操作、详情、接码、删除和平台动作。
- 对密码、Refresh Token 和邮箱使用默认隐藏/截断展示，复制操作仍然保留。
- 实时数据按唯一邮箱或唯一 ChatGPT 账号 ID 匹配；匹配不确定时不猜测、不复用旧额度快照。
- 数据缺失时显示明确的“暂无实时额度”或“尚无额度快照”状态，不生成模拟额度、价格或有效期。

## 卡片结构

1. 顶部：选择框、脱敏邮箱、实时账号状态和套餐。
2. 身份区：工作区、当前目标、号池、登录方式和用户 ID。
3. 异常区：把本地探测的认证/Codex 错误以可读提示呈现，并提供详情入口。
4. 凭据区：密码和 Refresh Token 的隐藏预览与复制按钮；可选备注单独显示。
5. 额度区：7 天窗口的已用百分比、重置时间、请求数、流量和已计费金额。实时投影缺少完整窗口时明确显示暂无数据，不再把旧快照或推导值当作剩余窗口。
6. 商务区（有数据才显示）：有效期、实际价格、倍率和最近检查时间。
7. 底部：创建时间与详情、接码、试用链接、删除及平台动作。

## 布局与响应式

- 使用语义化表格行承载卡片，以保留键盘/辅助技术的记录边界；视觉层将 `tbody` 转为 CSS Grid。
- `auto-fit` 网格在宽屏展示多列，680px 以下切为单列；工具栏和分页在窄屏换行。
- 使用主题 token 注入 CSS 自定义属性，兼容现有暗色/亮色主题；交互保留可见焦点和 180ms 状态过渡，并尊重减少动效设置。

## 验证

- `AccountCard.test.tsx` 覆盖身份、套餐、实时额度、匹配不确定、缺失数据、选择和复制行为。
- `Accounts.test.tsx` 覆盖列表请求实时投影并保持现有回归断言通过。
- 发布前运行前端全量测试、ESLint、TypeScript/Vite 生产构建，并在浏览器中检查桌面与 390px 移动视口。
