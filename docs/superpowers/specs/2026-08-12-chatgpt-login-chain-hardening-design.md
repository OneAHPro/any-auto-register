# ChatGPT 登录链路加固设计

## 目标

让现有 ChatGPT 登录接码链路在真实邮箱页面结构、短暂 OAuth 状态异常和并发任务统计场景下稳定完成，并确保任务结果能反映 Codex2API 同步状态。

## 范围

本次包含：

1. MailAPI 单邮件页面解析、Cloudflare 链接过滤和详情失败回退。
2. 手机 OAuth 事务未就绪时的单次全新会话重试。
3. 并发任务按已完成账号数更新进度，终态强制收敛到总数。
4. 任务终态等待 Codex2API 后台同步结束，并保留同步成功/失败日志。
5. 邮箱验证码日志脱敏及重复 MailAPI 入口日志收敛。
6. 自动化重登任务复用同一邮箱解析、终态进度和额度告警路径，并验证任务互斥与每轮额度告警。

本次保持现状：

- WhatsApp/SMS 仍使用现有换号获取验证码流程，不新增额外多次验证策略。
- 不调整 LeadBee 的卡密结算语义和现有并发槽位模型。
- 不改变自动化每轮低于额度阈值即发送告警的行为。

## 数据流

```text
邮箱入口
  -> 识别单邮件页或列表页
  -> 解析正文、主题、收件时间、消息指纹
  -> OAuth 邮箱 OTP
  -> 手机 OAuth 上下文检查
  -> 必要时新建一次 OAuth 会话重试
  -> 现有 LeadBee/SMS 流程
  -> 保存 Refresh Token
  -> 可追踪 Codex2API 同步
  -> 按完成回调更新任务计数
```

## 错误策略

- MailAPI 详情请求返回非 2xx、Cloudflare 保护路径或正文未含验证码时，回到原始页面解析；原始页面也未找到验证码时才继续轮询。
- OAuth 事务未就绪只允许一次全新浏览器/OAuth 上下文重试，第二次失败才记录账号失败。
- WhatsApp、SMS 超时和 Invalid OTP 继续沿用当前号码/卡密状态处理，避免重复消费服务商资源。
- Codex2API 同步结果记录为成功、远端已存在或失败；同步失败保留在本轮任务日志中，但不改变账号已经完成登录的成功计数。

## 验证标准

- 191006.xyz 风格单邮件页面能直接提取验证码和邮件时间，不请求 `/cdn-cgi/l/email-protection`。
- 所有 MailAPI 详情候选失败时能回退到原始页面。
- OAuth 事务未就绪测试第一次重试成功，且不会触发第二次以上重试。
- 并发任务终态的 `progress` 等于 `total/total`，并且按完成数单调递增。
- 验证码不会以明文写入任务日志。
- 自动化重登测试确认成功、额度不足告警、额度已用完失败忽略、额度查询失败跳过额度告警和任务互斥均保持成立。
- 全量测试、构建、服务重启和线上健康检查通过后，再重跑指定 4 个账号。
