# ChatGPT 自动化额度不足告警设计

## 目标

在现有 ChatGPT 自动鉴权、重登和 Codex2API 同步任务结束时，重新读取 Codex2API 全部账号的最新 7d 使用率与成本，计算正常可用账号的估算剩余额度。用户可在后台设置美元阈值；每轮统计值严格低于阈值时发送一封额度不足邮件。

同时精简现有重登失败告警邮件：所有业务告警只展示汇总信息，不再列出逐账号邮箱、使用率、成本或剩余额度。

## 用户可见行为

### 后台设置

在“ChatGPT 自动重登 → 邮件告警”区域新增：

```text
Codex2API 剩余额度告警阈值（美元）
```

- 配置键：`chatgpt_auto_relogin_quota_alert_threshold_usd`。
- 支持最多两位小数。
- 允许范围：`0.00`–`10000000.00` 美元。
- 默认值为 `0.00`，表示额度不足告警未启用。
- 保存后从下一轮自动任务开始生效，无需重启服务。

设置页帮助文案明确说明：每轮自动鉴权结束后，估算剩余额度严格低于该值时发送一封邮件；自动化每 5 分钟运行时，额度持续低于阈值就每 5 分钟发送一次。

### 额度不足触发规则

任务结束时取得最新额度报告后判断：

```text
阈值 > 0 且估算剩余额度 < 阈值
```

边界采用严格小于：当前额度等于阈值时不发送。

每轮独立判断，不保存“已告警”状态，不做冷却、去重或恢复通知。例如阈值为 `$1200.00`：

```text
14:00  $1180.40 → 发送
14:05  $1170.10 → 再次发送
14:10  $1210.00 → 不发送
14:15  $1190.00 → 发送
```

### 两类邮件相互独立

现有“仍有额度的重登失败账号达到数量阈值”规则保持不变。额度不足告警是第二个独立条件：

- 只达到重登失败阈值：发送一封重登失败告警。
- 只低于额度阈值：发送一封额度不足告警。
- 同时满足两个条件：发送两封不同标题的告警邮件。
- 两个条件都未满足：不发送业务告警。

## 额度统计口径

自动任务完成账号重登和 Codex2API 同步后，再次调用 Codex2API 管理接口：

```text
GET /api/admin/accounts?channel=codex
```

该读取只取得最新账号清单，不重新触发 wham 探针。正常可用账号沿用第一版口径：

- Codex2API 状态为 `active` 或 `rate_limited`；
- `usage_percent_7d` 和 `billed_7d` 是有效数字；
- 7d 使用率大于 0 且小于 100%；
- 成本为非负数字。

逐账号估算公式保持不变：

```text
估算剩余额度 = billed_7d × (100 - usage_percent_7d) ÷ usage_percent_7d
```

每个账号先按美元四舍五入到两位小数，再求和得到本轮 `estimated_remaining_usd`。重置时间不读取、不参与计算、不展示。

邮件中的“正常可用账号”数量只统计成功得到有效估算值的账号。Codex2API 全部远端账号数量单独展示为“账号总数”。

## 邮件标题

所有业务告警标题统一采用：

```text
剩余额度｜正常可用账号｜告警标题
```

额度不足告警示例：

```text
$1180.40｜正常可用账号 18 个｜Codex2API 剩余额度不足告警
```

重登失败告警示例：

```text
$1180.40｜正常可用账号 18 个｜ChatGPT 重登失败账号告警
```

标题中的金额和账号数量来自任务结束时的最新额度报告。若结束时额度查询失败，重登失败告警继续使用任务开始时已经取得的账号快照生成标题；额度不足告警跳过该轮判断。

## 邮件正文

纯文本和 HTML 邮件都移除逐账号明细，只保留汇总：

- 当前估算剩余额度（美元）；
- 正常可用账号数量；
- Codex2API 账号总数；
- 额度不足告警阈值（仅额度不足邮件）；
- 仍有额度的重登失败数量；
- 额度已用完的重登失败数量；
- 完整重登失败数量；
- 已删除或停用账号数量；
- 任务 ID；
- 北京时间统计时间。

重登失败邮件说明“仍有额度的重登失败数”是触发指标。额度不足邮件说明本轮额度严格低于后台阈值，并注明金额为根据真实 Codex2API 7d 数据计算的估算值。

邮件不包含账号邮箱、远端账号 ID、令牌、密码、Admin Key、SMTP 凭证或额度重置时间。

## 后端设计

### 配置 API

`api/config.py` 将 `chatgpt_auto_relogin_quota_alert_threshold_usd` 加入配置白名单和返回字段。使用 `Decimal` 校验最多两位小数及 `0.00`–`10000000.00` 范围，规范化存储为两位小数字符串。

### 最新额度读取

`services/chatgpt_codex2api_health.py` 新增一个只读函数，复用现有 Codex2API URL、Admin Key、请求超时、错误净化和账号行归一化逻辑，返回全部远端额度行。该函数不触发 probe，也不读取重置时间。

### 自动任务接线

`api/tasks.py` 在自动任务业务状态确定为 `done` 后、发送邮件前读取最新额度。成功时生成并记录：

- `codex2api_account_count`
- `available_quota_account_count`
- `estimated_remaining_usd`
- `quota_alert_sent`
- `quota_alert_reason`
- `quota_alert_threshold_usd`

任务元数据只保存汇总，不保存逐账号数据。

重登失败邮件和额度不足邮件共享同一份最新额度报告，避免同一轮使用不同金额。最新读取失败时：

- 记录净化后的任务日志与 `quota_alert_reason=quota_query_failed`；
- 跳过额度不足条件；
- 重登失败告警仍按原数量条件执行，并使用任务开始时的额度快照生成标题汇总。

### 邮件服务

`services/chatgpt_auto_relogin_alerts.py` 保留现有 SMTP 连接、凭证保护与测试邮件逻辑，拆分为两个业务入口：

- `send_auto_relogin_alert(...)`：数量阈值告警；
- `send_quota_threshold_alert(...)`：美元额度阈值告警。

两个入口共享发件人解析、额度标题格式和汇总正文构建逻辑。额度不足入口在阈值为 0、当前额度等于或高于阈值时不连接 SMTP。

## 前端设计

`ChatGPTAutoReloginSection` 在现有“重登失败告警阈值”下方增加美元输入框：

- 标签：`Codex2API 剩余额度告警阈值（美元）`；
- `min=0`；
- `max=10000000`；
- `precision=2`；
- 默认 `0`；
- 帮助文案说明 0 表示关闭以及每轮重复发送语义。

`Settings.tsx` 在配置加载和提交时保留两位小数，不使用现有整数归一化函数。其他 SMTP 表单与自动化状态轮询保持不变。

## 故障与边界处理

- 阈值为空时按 `0.00` 返回和保存。
- 阈值为负数、超过上限、非数字或小数超过两位时，配置 API 返回 400 并保持原配置。
- 当前估算额度等于阈值时不发送。
- SMTP 未配置或发送失败只记录告警结果，不改变已经完成的自动任务状态。
- 额度查询失败不把额度当成 `$0.00`，避免误发额度不足邮件。
- 正常账号数量为 0 且有效额度合计为 `$0.00` 时，只要阈值大于 0，就发送额度不足告警。
- 手工重登、停止任务和异常终止任务不执行额度不足告警。

## 测试策略

### 后端

- 配置默认值、两位小数保存、0 关闭、上下限和非法值校验。
- 任务完成后进行一次最新额度读取；手工、停止和异常任务跳过。
- 当前额度低于阈值时每轮都调用 SMTP，不读取上轮告警状态。
- 当前额度等于或高于阈值时不连接 SMTP。
- 同一轮同时达到两个条件时发送两封邮件。
- 最新额度查询失败时额度告警跳过，重登失败告警继续执行。
- 两种业务邮件标题都按“金额｜正常可用账号｜标题”生成。
- 纯文本与 HTML 均不包含任何账号邮箱或逐账号表格。
- 邮件继续隐藏令牌、Admin Key 和 SMTP 密码。

### 前端

- 新输入框展示默认值 0、范围和两位小数精度。
- 已保存的小数阈值正确加载和提交。
- 帮助文案明确每轮重复发送。
- 现有自动重登、重登失败阈值和 SMTP 测试交互保持通过。
