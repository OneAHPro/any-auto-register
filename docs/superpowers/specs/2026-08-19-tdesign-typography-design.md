# TDesign 字体系统接入设计

## 目标

将前端从当前系统默认字体栈切换为腾讯 TDesign 字体系统，使页面中的中文、英文和数字形成一致的字体规范，并确保本地开发、构建产物和线上部署的显示效果一致。

## 字体策略

- 将 TDesign 官方 `TCloudNumberVF.ttf` 作为项目静态资源随前端发布，不依赖访问者电脑是否安装字体。
- 数字、金额、配额、时间和统计数据优先使用 `TCloudNumber`。
- 中文使用 TDesign 官方界面字体栈：`PingFang SC`、`Microsoft YaHei`、`Arial`、`sans-serif`。
- 全局字体栈以 `TCloudNumber` 开头。浏览器对该字体不包含的中文字形自动使用后续中文字体，因此中文和数字可在同一套全局规则下显示。
- 日志、代码、Token、邮箱及其他需要字符对齐的内容保留现有等宽字体，不强制使用数字字体。

## 接入范围

1. 在前端公共字体目录保存官方字体文件。
2. 在全局样式中通过 `@font-face` 注册 `TCloudNumber`，并声明统一的字体 CSS 变量。
3. 将全局 `body` 字体切换到 TDesign 字体栈。
4. 在 Ant Design 明暗主题中同时设置 `fontFamily`，使菜单、按钮、表格、表单、弹窗、通知和浮层继承同一规则。
5. 为日志面板、`pre`、`code` 及明确的技术数据区域保留等宽字体规则。

## 加载与回退

- 字体声明使用 `font-display: swap`，避免字体下载期间出现不可见文字。
- 官方字体加载失败时，数字和中文均回退到 TDesign 的系统字体栈，页面功能及排版仍可使用。
- 字体文件由 Vite 构建并进入静态资源，不请求第三方 CDN。

## 验证

- 增加前端自动化检查，确认明暗主题均声明统一的 TDesign 字体栈。
- 构建后检查字体资源被正确输出，并且 CSS 引用的是构建后的本地资源。
- 运行完整前端测试、类型检查和生产构建。
- 在桌面宽度和移动宽度各检查一个包含中文、数字、表格和弹窗的代表页面。
- 检查日志/代码区域仍使用等宽字体且内容没有错位。

## 非目标

- 本次不修改字号、行高、字重层级、颜色、间距或页面布局。
- 本次不迁移到 TDesign 组件库，继续使用现有 Ant Design 组件。
- 本次不调整后端、数据库、账号任务或线上业务数据。
