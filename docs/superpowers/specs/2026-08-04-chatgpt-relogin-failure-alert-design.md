# ChatGPT 重登失败账号告警设计

## 目标

将现有“鉴权失效或重登失败任一达到阈值”的自动认证告警，收敛为只针对最终重登失败账号的告警。每轮自动鉴权正常完成后，当重登失败账号数大于等于用户配置阈值时发送一封邮件；阈值默认 20，仍允许用户在设置页修改。

告警邮件需要以北京时间展示完成时间，并按固定顺序突出展示四项统计：账号总数、成功账号、鉴权失败、重登失败。

## 用户可见行为

- 设置项名称改为“重登失败告警阈值（账号数）”。
- 未配置时默认阈值为 20，允许范围保持 1–10000。
- 阈值采用包含边界的判断：配置为 20 时，重登失败 19 个不发送，20 个及以上发送。
- 鉴权失败数量仅用于展示，不参与是否发送邮件的判断。
- 每轮正常完成的自动任务最多发送一封；手工任务、停止任务和异常终止任务不发送。
- 任务日志明确区分“重登失败数未达到阈值”“重登失败告警已发送”“已达到阈值但 SMTP 未配置”和“邮件发送失败”。

## 统计口径

邮件四项指标来自同一轮自动鉴权任务：

1. **账号总数**：本轮纳入处理范围的账号数。
2. **成功账号**：本轮任务最终结果为成功的账号数，包括无需恢复即通过以及重登恢复成功的账号。
3. **鉴权失败**：Codex2API 自刷新后仍确认远端鉴权失败的账号数。
4. **重登失败**：进入完整重登流程后仍未成功、且未因明确删除或停用而从本地移除的账号数。

鉴权失败与重登失败是过程指标，不是互斥分类；同一账号可能先被计入鉴权失败，随后又被计入重登失败。邮件会明确说明四项指标不应相加核对总数。

## 后端设计

### 配置兼容

继续使用现有配置键 `chatgpt_auto_relogin_alert_threshold`，避免新增配置迁移。统一将下列未配置默认值改为 20：

- 告警服务常量；
- 配置 API 的回填值；
- 前端表单初始值和配置归一化回退值。

已经保存的值不会被代码静默覆盖；生产部署后显式把当前服务器配置设置为 20。

### 触发规则

`send_auto_relogin_alert` 只判断：

```text
relogin_failed_count >= configured_threshold
```

`invalid_rt_count` 不再参与条件。SMTP 配置只在达到阈值后检查，低于阈值时不建立连接。函数继续返回结构化的 `sent`、`reason`、`threshold` 和可选 `error_type`，供任务元数据和日志使用。

### 任务接线

自动任务在确定最终状态为 `done` 后，将以下值传给告警服务：

- `total_accounts=total`
- `successful_accounts=success`
- `invalid_rt_count=invalid_rt_count`
- `relogin_failed_count=relogin_failed_count`

停止任务仍写入 `alert_reason=task_stopped` 并跳过告警。任务异常终止沿用现有失败收口，不触发邮件。

### 北京时间

告警服务使用标准库 `zoneinfo.ZoneInfo("Asia/Shanghai")` 显式生成北京时间，不依赖容器或宿主机的 `TZ`。展示格式为：

```text
2026-08-04 21:17:45（北京时间）
```

SMTP 测试邮件的测试时间也使用同一个格式化函数，避免同一配置模块出现不一致的时区表达。

## 邮件设计

邮件使用 `multipart/alternative`：纯文本作为兼容版本，HTML 作为主要展示版本。

主题格式：

```text
[Any Auto Register] ChatGPT 重登失败账号告警（{relogin_failed_count} 个）
```

主题中的数量使用本轮实际重登失败数；例如阈值为 20、实际失败 27 个时显示“27 个”。

HTML 正文结构：

1. 标题与“本轮自动鉴权已完成，重登失败数达到告警阈值”的摘要；
2. 响应式四指标表格，顺序固定为账号总数、成功账号、鉴权失败、重登失败；
3. 任务 ID、告警阈值、完成时间；
4. 指标口径说明和前往“任务运行”页面查看日志的提示。

颜色仅用于辅助识别：总数为中性蓝灰、成功为绿色、鉴权失败为橙色、重登失败为红色。邮件不包含账号密码、令牌、SMTP 凭证或其他敏感配置。所有动态文本在 HTML 中进行转义。

纯文本版本包含完全相同的四项统计、任务信息、北京时间和口径说明。

## 前端设计

设置页不新增表单或迁移入口，仅调整现有字段：

- 标签与无障碍名称：“重登失败告警阈值（账号数）”；
- 初始值：20；
- 帮助文案：“每轮自动鉴权完成后，重登失败账号数达到或超过此值时发送一封提醒；鉴权失败数仅展示，不触发告警。”

输入范围保持 1–10000，保存仍使用现有配置键。

## 故障与边界处理

- 重登失败数为负数、空值或非法值时按 0 处理。
- 阈值非法或小于 1 时回退为默认值 20。
- 达到阈值但 SMTP 配置不完整时不抛出任务异常，记录专用告警日志和原因。
- SMTP 发送失败只记录净化后的异常类型，不把凭证或服务端原始敏感文本写入任务日志。
- 邮件构建失败也由任务层捕获，已经完成的业务任务状态不回滚。

## 测试策略

### 后端单元测试

- 阈值 20、重登失败 19：不连接 SMTP。
- 鉴权失败远超 20、重登失败 19：仍不发送。
- 重登失败恰好 20：发送且每次调用只产生一封。
- 重登失败超过 20：发送。
- 使用非默认阈值 7 时，重登失败 6 不发送、7 发送，证明配置即时生效。
- 邮件主题、纯文本和 HTML 均包含四项指标、阈值和北京时间。
- HTML 动态字段完成转义，整封邮件不包含 SMTP 密码。
- 465/STARTTLS、AUTH LOGIN、缺少配置和发送失败行为保持回归通过。
- SMTP 测试邮件继续绕过业务阈值，并使用北京时间。

### 任务与配置测试

- 自动任务向告警函数传入最终成功数。
- 停止任务继续抑制告警。
- 告警结果和新日志文案写入任务元数据/日志。
- 配置 API 未设置时返回 20，范围校验保持 1–10000。

### 前端测试

- 设置项标签、帮助文案和默认值为新语义。
- 已保存阈值仍能正确加载、编辑和提交。
- 设置页完整回归和生产构建通过。

## 部署与验收

1. 运行聚焦后端、任务和前端测试，再运行完整后端测试与前端生产构建。
2. 提交并推送当前分支，使用既有无停机部署流程更新服务器。
3. 将生产配置 `chatgpt_auto_relogin_alert_threshold` 显式设置为 `20`，保留自动重登启用状态和现有巡检间隔。
4. 验证健康检查、配置 API、自动重登状态接口和容器日志。
5. 在不伪造失败账号、不发送误告警的前提下，通过服务器内纯构建检查验证邮件四项内容、HTML 结构和北京时间；业务触发路径由自动化测试覆盖。
