# ChatGPT 自动重登 RT 优先设计

## 目标

用一套新的 10 分钟自动任务替换原有“每 30 分钟对全部账号执行验证码重登”的行为。每轮先使用账号现有 Refresh Token 获取新令牌；只有 Refresh Token 被服务端明确判定失效时，才使用保存的邮箱、密码或 MFA 凭据执行完整登录。任何成功获取的新令牌都要保存到本地并覆盖同步到 Codex2API。

## 方案选择

考虑过三种实现：

1. 保留 30 分钟全量验证码重登。实现不变，但每轮需要读取邮箱验证码，速度最慢。
2. 每 10 分钟直接刷新全部 Refresh Token，失败一律验证码重登。速度较快，但会把网络超时和上游故障误判为 Refresh Token 失效。
3. 每 10 分钟刷新全部 Refresh Token，并区分“明确失效”与“暂时失败”。刷新成功时直接同步，只有明确失效才验证码重登，暂时失败留到下一轮重试。

采用方案 3。它符合用户确认的 RT 优先流程，同时避免短暂网络问题引发整批验证码登录。

## 用户可见行为

- 设置入口仍位于“全局配置 → Codex2API”。
- 自动任务只保留一套，周期改为 10 分钟；旧的 30 分钟全量验证码重登不会并行保留。
- 间隔配置范围改为 10–1440 分钟，默认值改为 10；现有本地配置在部署时更新为 10。
- 并发范围仍为 1–10，当前并发保持 10。
- 服务启动或首次启用后先等待完整的 10 分钟，不会立刻创建任务。
- 手动“重登所选”保持原行为：用户明确点击时，对所选账号执行完整登录并覆盖同步 Codex2API，不先走 RT 快速路径。
- 自动任务日志需要分别显示“RT 刷新成功并同步”“RT 明确失效，开始完整登录”“暂时失败，等待下轮重试”和“完整登录并同步成功”。
- 每轮自动认证都作为普通任务记录持久化到“任务运行”，来源显示为“自动认证”，并展示 RT 明确失效数、完整重登失败数和邮件提醒结果。
- ChatGPT 账号列表在账号总数后显示“下次执行”倒计时；运行期间显示“当前轮运行中”，关闭或暂无可用账号时显示对应状态。
- 设置页提供邮件告警阈值和 SMTP 配置。默认阈值为 5；一轮中“RT 明确失效数”或“完整重登失败数”任一达到阈值时，只发送一封汇总提醒，两个统计都低于阈值时不发送。

## 自动任务数据流

每个账号按以下顺序执行：

1. 加载本地账号及当前 Refresh Token。
2. 使用 OAuth `refresh_token` grant 请求新 Access Token。
3. 若刷新成功，原子保存新 Access Token；服务端返回轮换后的 Refresh Token 时同时覆盖旧值。
4. 使用保存后的新令牌按账号身份覆盖同步 Codex2API，并调用 Codex2API 远端测试接口确认新凭据可用。
5. 若刷新响应明确表示 Refresh Token 失效，则使用现有保存凭据执行完整登录，获取新 Access Token / Refresh Token，再执行相同的 Codex2API 覆盖与远端验证。
6. 若刷新属于暂时失败，不启动验证码登录，也不覆盖本地令牌；记录失败原因并留到下一轮自动任务重试。

成功计数的边界保持严格：只有本地新令牌已保存、Codex2API 已覆盖且远端测试通过，账号才计为成功。

## 每轮统计与邮件提醒

邮件判断只在一轮完整自动任务结束后执行，手工重登和被停止的自动任务不触发提醒：

1. `invalid_rt_count` 统计本轮被 OAuth 明确判定为 `invalid` 的 RT；随后完整登录是否成功都计入该数。
2. `relogin_failed_count` 只统计已进入完整登录但登录本身失败的账号。完整登录成功、仅 Codex2API 覆盖失败的账号不计入该数；明确停用并删除的账号也不计入重登失败。
3. 当 `invalid_rt_count >= threshold` 或 `relogin_failed_count >= threshold` 时发送一封汇总邮件；判断为包含阈值，例如阈值 5 时正好 5 个即发送。
4. 邮件包含任务 ID、账号总数、两项统计、阈值和完成时间，不包含账号令牌、验证码、邮箱密码或 SMTP 凭据。
5. SMTP 发送失败只写入脱敏后的任务元数据和日志，不改变该轮认证任务已经得到的成功/失败结果。
6. SMTP 访问凭证只存运行时配置，配置读取接口始终返回空密码；设置页密码留空表示保留原凭证。

## 忘记密码凭据耐久性与旧数据修复

`chatgpt_password_reset_url_mail` 账号不能只保存邮箱池文件名。完整登录成功后，账号自己的 `mailbox_login_context` 必须保存一份可独立恢复的凭据快照，包括账号类型、当前可用密码、收件 URL、可选的 TOTP URL、邮箱池文件名，以及 `password_reset_required=false`。账号主表的密码字段也要与最终实际密码保持一致。对外账号 API 和任务日志继续递归隐藏这些字段。

旧账号按以下顺序恢复：

1. 优先使用账号 `mailbox_login_context` 中的自包含凭据。
2. 缺字段时再读取原邮箱池记录补齐收件 URL、TOTP URL 和密码。
3. 邮箱池缺少密码但账号主表仍保存可用密码时，使用主表密码，并把该记录视为已经完成密码重置。
4. 若保存的密码被 OpenAI 密码校验端点以 `401` / `invalid_credentials` 明确拒绝，且账号类型支持收件 URL 忘记密码，则只额外重试一次忘记密码流程；网络超时、403、Sentinel 或其他暂时错误不触发密码重置。
5. 账号与邮箱池都没有密码、但仍有收件 URL 时，生成新密码并重新执行忘记密码流程；成功后同时更新账号主表、账号凭据快照和邮箱池中的已使用记录。
6. 密码和收件入口都缺失时返回明确的 `credentials_incomplete` 阶段，不把它误报为网络、OAuth 或 Codex2API 故障。

这套兼容路径既修复后续新账号的持久化，也能直接覆盖现有“邮箱池仍可收件但新密码为空”的历史账号。

## Refresh Token 结果分类

刷新结果使用三态模型：

- `valid`：OAuth 刷新返回成功且包含新的 Access Token。
- `invalid`：上游返回明确的 `invalid_grant`、`token_invalidated`、`refresh_token_invalidated`，或等价的 Refresh Token 已撤销/失效错误码。
- `transient_error`：连接超时、DNS/TLS 错误、HTTP 429、HTTP 5xx，以及无法确认令牌状态的其他响应。

只有 `invalid` 进入完整验证码登录。`transient_error` 不修改账号状态，不触发邮箱取码。账号被明确判定删除或停用时继续沿用现有删除/停用处理，不循环重登。

## 任务互斥与优先级

任务互斥不是保留旧任务，而是防止多套任务同时操作相同账号：

1. 旧的 30 分钟自动任务由新的 10 分钟 RT 优先任务替换。
2. 同一时刻最多运行一轮自动任务；上一轮超过 10 分钟时，下一轮不叠加，也不补发积压轮次。
3. 手工注册、登录、接码和手工重登优先。手工任务开始时，自动任务停止派发新账号；正在安全步骤中的账号完成或退出后释放执行权。
4. 自动任务因手工任务繁忙而未能启动时，维持当前到期时间并持续重试；繁忙结束后只启动一轮。
5. 单账号继续使用现有账号锁，避免手工重登与自动 RT 刷新同时覆盖同一账号的令牌。

## 代码边界

- `platforms/chatgpt/token_refresh.py`：返回结构化刷新状态、HTTP 状态和脱敏错误码，不负责完整登录或 Codex2API 同步。
- `services/chatgpt_relogin.py`：新增自动账号编排入口，在账号锁内执行 RT 刷新、令牌持久化、必要时完整登录以及 Codex2API 覆盖验证。现有手工完整重登入口保持不变。
- `core/applemail_pool.py` 与 `core/base_mailbox.py`：允许忘记密码流程安全更新已经消费的指定邮箱记录，并同步更新内存中的邮箱账号凭据。
- `platforms/chatgpt/plugin.py`：成功后保存最小但自包含的 ChatGPT 登录凭据快照，不再只保存账号类型和邮箱池文件名。
- `api/tasks.py`：根据任务元数据中的 `automation=true` 选择 RT 优先入口；手工任务继续选择完整重登入口，并汇总不同阶段的结果。
- `services/chatgpt_auto_relogin_alerts.py`：按每轮汇总结果和配置阈值发送 SMTP 邮件；587 加密连接使用 STARTTLS，465 使用 SMTP SSL。
- `services/chatgpt_auto_relogin.py`：间隔下限和默认值改为 10 分钟；持久化状态机、重启恢复和互斥逻辑继续复用。
- `frontend/src/components/settings/ChatGPTAutoReloginSection.tsx` 与 `frontend/src/pages/Settings.tsx`：显示 10 分钟最小值、默认值、告警阈值和 SMTP 设置，不新增第二个定时任务开关。
- `frontend/src/pages/RunningTasks.tsx`：标记自动认证任务并显示每轮告警统计。
- `frontend/src/pages/Accounts.tsx`：读取自动任务状态并显示下一轮倒计时。

## 失败与数据安全

- 刷新成功后必须先保存服务端轮换的新 Refresh Token，再同步 Codex2API，避免继续使用已经被轮换替代的旧值。
- Codex2API 覆盖失败时保留本地新令牌，任务明确标记为同步阶段失败，下一轮可重新同步。
- RT 暂时失败时保留原令牌，不写入空值、不修改为 invalid，也不触发验证码。
- 完整登录失败时保留此前仍可恢复的本地记录；账号明确删除或停用时按现有策略移除。
- 忘记密码成功后，新密码必须在同一次成功路径中更新账号主表、账号凭据快照和邮箱池记录；任一关键持久化步骤失败都不得宣告完整登录成功。
- 日志继续隐藏 Refresh Token、Access Token、邮箱验证码、授权码和管理密钥。
- 服务重启会把遗留运行任务标记为停止，并在一个完整周期后重新安排，不从中间账号位置盲目续跑。

## 测试与验收

后端测试必须先失败再实现，并覆盖：

- RT 刷新成功时不调用完整登录，保存轮换后的 AT/RT，并覆盖验证 Codex2API。
- `invalid_grant`、`token_invalidated` 和 `refresh_token_invalidated` 才调用完整登录。
- 超时、429 和 5xx 不调用完整登录，保留旧令牌。
- Codex2API 同步失败与 RT 刷新失败使用不同阶段和错误信息。
- 自动任务调用 RT 优先入口，手工重登仍调用完整登录入口。
- 新注册的忘记密码账号保存自包含凭据；历史账号可从主表密码恢复，或在仅保留收件 URL、以及旧密码被服务端明确拒绝时重新设置并持久化新密码。
- 已使用邮箱池记录能够按指定邮箱更新新密码，但不会重新进入可领取状态。
- 10 分钟首次排期、到期触发、繁忙延迟、长任务不重叠、重启恢复和配置边界。
- 任务日志及持久化结果不泄露任何令牌或验证码。
- 邮件阈值采用包含边界，低于阈值不建立 SMTP 连接；配置读取不回传 SMTP 密码，密码留空保存不会清空现有凭证。
- 每轮任务元数据持久化两项计数与邮件结果；前端任务历史和账号页倒计时正确展示自动状态。

前端测试覆盖 10 分钟最小值、默认值、保存 payload、SMTP 设置、任务历史统计和状态倒计时。完成后运行相关后端测试、后端全量测试、前端全量测试、前端生产构建和 Docker 本地部署验证。部署验证需要确认状态接口显示 10 分钟周期、SMTP 密码不回传，并用受控测试账号分别验证 RT 成功快速路径和明确失效后的完整登录回退路径。
