# MailAPI HTML 邮件新鲜度识别设计

## 问题

`mail.ai1998.xyz` 的详情页返回 HTML，并在同一页面按新到旧排列多张
`article.mail-card`。现有解析器把整页视为无时间、无消息 ID 的文本，因此发送
OTP 后会先提交页面中原有的旧验证码；旧码失败后只能依靠验证码字符串去重，
无法可靠判断邮件是否属于本次登录。

## 方案

在 `MailApiUrlOtpBackend._parse_mailapi_message` 中增加有界 HTML 解析：

1. 只读取第一个 `article.mail-card`，它代表页面当前最新邮件。
2. 从该卡的 `span.date` 读取收件时间，并复用现有时间解析函数。
3. 使用该卡的主题、时间和正文摘要生成不可逆的稳定消息 ID。
4. 将该卡作为验证码提取范围，避免后续旧邮件干扰。
5. `wait_for_code` 继续使用现有 `otp_sent_at` 和基线 ID 逻辑：早于本次发送
   时间的邮件直接跳过；新 ID 且时间不早于发送时间时才返回验证码。

没有 `mail-card` 的普通 HTML、JSON MailAPI 和其他邮箱后端保持现有行为。
轮询间隔、20 秒转后台和 180 秒总等待上限均不改变，因此不会增加服务器负载。

## 验证

- 新增回归测试：旧 HTML 邮件含验证码但时间早于 OTP 发送时间时，返回空。
- 新增回归测试：页面更新为新邮件卡后，返回新验证码并且基线消息 ID 发生变化。
- 保留并运行现有 MailAPI JSON、列表发现、URL 隐私和登录流程测试。

## 部署与回滚

测试通过且服务器没有运行中任务后发布新 release，原 release 和邮箱池文件继续
保留；出现异常时可将 `current` 链接切回上一 release。
