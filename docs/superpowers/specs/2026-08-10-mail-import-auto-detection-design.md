# 邮箱导入自动识别设计

## 目标

邮箱导入默认不再依赖用户先选择 Outlook、Hotmail、MailAPI URL 或 AppleMail。系统读取粘贴内容后逐行识别存储后端和账号格式，用户确认一次即可完成导入。

现有类型选择仍保留，用于查看、筛选和删除不同邮箱池中的记录，也作为少数歧义格式的手动兜底。已有 `/api/mail-imports` 手动类型请求、预览接口、删除接口和邮箱裂变行为保持兼容。

## 方案比较

### 采用：后台权威识别，前端实时展示结果

新增纯解析检测器和自动导入编排器。前端粘贴内容后调用检测接口，只显示各类型匹配数量和无法识别的行；正式导入仍由后台重新检测，不信任前端判断。

优点是判断逻辑只有一个权威来源，支持跨类型内容，旧接口仍可手动指定；缺点是增加一个检测接口和组合结果结构。

### 未采用：只在前端根据字符串切换下拉框

实现较快，但接口调用仍可提交错误类型，前后端规则也容易漂移。它只能改善视觉操作，不能保证数据进入正确邮箱池。

### 未采用：依次尝试所有导入器

对每行执行多个导入器会触发无意义的 OAuth 可用性请求，并可能在判断完成前写入文件或数据库。失败原因也会混杂，无法可靠回滚。

## 自动识别规则

检测器逐行处理文本，忽略空行、注释和供应商说明。JSON 对象或数组沿用 AppleMail 现有 JSON 解析能力。

文本规则按高置信度从上到下匹配：

1. `邮箱----http(s)://...` 两段格式识别为 Microsoft 存储下的 `mailapi_url`。
2. `邮箱----密码----MFA秘钥` 三段格式识别为 AppleMail 存储下的 ChatGPT 密码加 TOTP。
3. 忘记密码标记加收件 URL，以及包含收件 URL、2FA URL 的三段或四段格式，识别为 AppleMail URL 凭据。
4. 四段 OAuth 格式中，`outlook.*`、`hotmail.*`、`live.*`、`msn.*` 和 Microsoft 明确域名识别为 Microsoft OAuth；`icloud.com`、`me.com`、`mac.com` 识别为 AppleMail。
5. 其余四段 OAuth 格式只有在字段具有明确提供商特征时才自动归类。无法可靠区分的行标记为“需要手动指定”，不写入任何邮箱池。

同一个邮箱在同一批内容中只能出现一次。重复行在编排阶段报错，避免分别进入两个邮箱池。

## 后端结构

新增 `services/mail_imports/auto_detection.py`，负责：

- 解析可操作行，不保存原始凭据。
- 产出每行的提供商、账号子类型、置信状态和安全错误。
- 按 `microsoft`、`applemail` 分组。
- 对 URL、令牌和长密钥执行错误脱敏。

新增自动导入编排器，复用现有 `MicrosoftMailImportStrategy` 和 `AppleMailImportStrategy`：

- 单一提供商批次沿用原有导入、配置绑定和响应。
- 跨提供商批次分别执行两个策略，汇总成功、失败与分组结果。
- 混合批次不擅自修改当前默认邮箱来源；导入前的配置保持不变。
- 邮箱裂变参数只作用于识别出的 Microsoft 记录。
- AppleMail 文件名和目录参数只作用于 AppleMail 分组。

`MailImportExecuteRequest.type` 增加 `auto`，现有 `microsoft` 和 `applemail` 请求语义不变。新增 `POST /api/mail-imports/detect`，只返回计数、提供商、行号、邮箱和安全错误，不返回密码、URL、MFA 或令牌。

## 前端交互

邮箱池类型下拉框继续控制当前预览、单条删除和批量删除，不再默认决定导入内容的类型。

导入区域默认显示 `自动识别`：

- 内容为空时显示支持格式摘要。
- 粘贴后防抖调用检测接口，显示 Microsoft、AppleMail、无法识别的数量。
- 检测到 Microsoft 记录时显示现有邮箱裂变设置；裂变只影响 Microsoft 分组。
- 检测到 AppleMail 记录时显示可选文件名。
- 存在无法识别行时，列出行号和安全原因，并提供“按当前邮箱池类型导入”的手动兜底动作。
- 确认导入默认提交 `type=auto`，成功后刷新所有受影响邮箱池，并自动切到最近导入的分组查看结果。

手动兜底使用现有类型下拉框和原有请求，不新增第二套导入表单。

## 错误与一致性

- 检测接口不产生数据库或文件写入。
- 正式导入会重新检测，避免内容在预览后被修改。
- 单行识别失败不阻止同批其他高置信度行导入；零条可识别记录时返回 400。
- 分组导入保持现有部分成功语义，响应分别报告每个后端的成功和失败数。
- 混合批次中一个后端失败时，另一个后端已成功的记录保留，并在结果中明确显示，不伪装成整体失败。
- 所有错误沿用现有凭据脱敏要求，不输出 MailAPI URL、密码、MFA、client_id 或 refresh_token。
