# SMS 接码池完整卡密展示设计

## 目标

SMS 接码池的“接码卡密”列表直接显示完整卡密，复制按钮复制完整原文，不再向当前用户展示脱敏值。

## 范围

- 仅修改受登录鉴权保护的 `/api/sms-pool` 列表响应和 `SMS接码池` 管理页面。
- 任务日志、错误信息、登录流程上下文中的卡密继续脱敏，避免把卡密写入长期日志。
- 不增加“显示/隐藏”开关；页面加载后始终显示完整卡密。
- 不修改卡密的导入、领取、使用、恢复和状态流转。

## 接口设计

`api.sms_pool._serialize_item()` 在现有列表项中新增：

```json
{
  "code": "完整卡密原文",
  "code_hint": "兼容旧客户端的脱敏提示"
}
```

新增 `code` 而不是把 `code_hint` 改成原文，避免字段含义与内容冲突，也保留旧客户端兼容性。接口继续受现有 API 登录中间件保护。

## 前端设计

`SmsPoolItem` 增加必需的 `code` 字段。“接码卡密”表格列改为读取 `code`：

- 单元格显示完整 `code`；
- Ant Design 的复制按钮使用完整 `code`；
- 空值使用 `-` 兜底，不再显示 `****`；
- 其他列、筛选、分页和五秒刷新行为不变。

## 测试

- 后端列表测试导入一张包含明显中间段的卡密，断言响应的 `code` 与数据库原文完全一致，同时保留脱敏 `code_hint`。
- 前端测试模拟同时包含完整 `code` 和脱敏 `code_hint` 的响应，断言页面出现完整卡密且不显示脱敏值。
- 前端测试触发复制按钮，断言写入剪贴板的是完整卡密。
- 运行 SMS 接码池聚焦后端测试、前端测试、完整后端/前端回归与生产构建。

## 部署验收

部署后读取生产 `/api/sms-pool` 响应确认存在完整 `code`，并验证公网前端资源包含使用 `code` 的新版本。保留上一 release 和部署前数据库备份作为回滚点；本次部署不修改数据库结构或现有卡密数据。
