# 探针额度汇总恢复设计

## 目标

修复自动鉴权任务长期显示 `$0.00` 或“本次探针额度未生成”的问题，同时保持 Codex2API 鉴权、重登录和多目标调度边界不变。

## 根因

多目标改造后，最终额度读取只保留与本地 assignment 邮箱匹配的远端账号，Codex2API 中手工导入但尚未进入本地资产表的账号被排除。生产环境中被保留的四个账号均已用满或缺少成本字段，因此汇总为零。

Codex2API 的账号列表会同步查询 5h/7d 成本。在 PostgreSQL 聚合超时时，使用率仍存在，但 `billed_7d` 会短暂返回空值。当前任务把任意正常账号的成本缺失视为整轮无效。

## 设计

### 额度读取范围

最终额度汇总读取所有已启用 Codex2API 目标的账号，而不是只读取本地已分配账号。鉴权探针、重登录和凭证覆盖仍按本地 assignment 路由，不扩大操作范围。

跨目标出现相同邮箱时按稳定邮箱身份去重。优先选择本地 assignment 指向的目标；没有本地身份时选择额度字段更完整、探针时间更新的记录。无邮箱行使用目标 ID 与远端账号 ID 作为独立身份。

### 额度完整性

- 当 `usage_percent_7d >= 100` 时，剩余额度确定为 `$0.00`；`billed_7d` 缺失不再使该账号变成无效数据。
- 活跃账号仍要求使用率和成本同时有效，继续使用现有估算公式。
- 同一任务内，如果当前响应的某个窗口暂时缺少成本，而前一次响应中同一账号、同一重置窗口有完整数据，则复用完整窗口快照，并标记为 fallback。
- fallback 金额可以展示，但 `quota_total_fresh=false`，本轮不发送额度阈值告警。
- 重置窗口发生变化时不复用旧数据。
- `at-import-*` 临时占位行不参与完整性判断；没有真实 email 的普通行按 `target_id + remote_id` 隔离，避免跨账号去重或复用。

### 用户界面

任务仍在做终态额度后处理、元数据为 `pending` 时，卡片显示“本次探针额度统计中”，避免把尚未完成误报为未生成。真正查询失败后继续显示“本次探针额度未生成”。

## 验证

1. 单元测试覆盖远端手工账号进入最终汇总、跨目标邮箱去重及 assignment 优先级。
2. 单元测试覆盖已用满且成本缺失、同轮 fallback 和重置窗口切换。
3. 任务测试覆盖 fallback 可展示但不触发额度告警。
4. 前端测试覆盖终态任务 `pending` 元数据仍显示统计中。
5. 发布后以只读方式核验生产 Codex2API 账号总数、可用账号数、任务额度元数据、服务健康和数据库完整性。
