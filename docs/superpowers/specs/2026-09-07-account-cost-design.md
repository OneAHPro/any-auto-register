# 账号购入成本

用户已确认按现有卡片风格直接实现、人民币计价，并提交部署上线。

在卡片“号池 / 登录方式”区域增加“账号成本”。没有金额时显示“未设置”；有值时显示 `¥12.50`，零元显示 `¥0.00`。点击成本打开独立小弹窗，支持保存、取消和清空；清空发送 null，恢复“未设置”。本地账号和已入库的远端托管账号均可编辑。旧版临时负数 ID 记录在完成库存入库后可编辑。

金额通过现有 `PATCH /accounts/{id}` 接口更新，输入字段为 `purchase_cost_cny`，不复用“实际价格”。服务端用 Decimal 校验非负、有限、至多两位小数及 `999999999.99` 上限，拒绝布尔值；持久化到独立 nullable INTEGER 列 `accounts.purchase_cost_cents`，避免凭据刷新整块写回扩展 JSON 时丢失成本。响应在 `extra_json.purchase_cost_cny` 投影为两位小数字符串。字段省略表示保留，显式 null 表示清空。旧账号列值为 NULL，旧扩展同名键不作为回退；凭据保存、重新登录、远端库存同步不修改成本列。

弹窗保存时禁用重复提交，失败保留输入并展示错误。成功只更新对应账号成本，保留列表的额度和状态。成本按钮支持键盘，阻止卡片双击详情事件；金额在桌面三列和窄屏两列布局下保持可读。

验证覆盖写入、修改、清空、零元、非法金额、省略不变、同步和重新登录保留、取消、错误重试、同邮箱不同账号独立编辑。部署使用不可变 release、SQLite 在线备份、服务和公开健康检查。

## 全部费用与价格

卡片额度区三个指标为居中等分的“请求数 / 已计费 / 价格”，删除该区域原有状态值。上方账号状态标签保留。

“已计费”仅使用 Codex2API 单账号 `GET /api/admin/accounts/{id}/usage?days=0` 返回的 `total_account_billed`，与用量弹窗“全部总费用”一致。上游源码及线上接口已核实 `period_days=0`；示例原始值 `12604.598858749765` 显示 `$12604.60`。接口按目标节点和远端账号 ID 匹配，只查询当前页，限制 4 个并发请求，并对成功缓存 60 秒、错误缓存 15 秒；刷新操作跳过缓存但复用尚未完成的同账号请求。整页费用最多等待 5 秒，超时取消未开始任务，已开始任务结束后更新缓存；上轮被取消的任务保持排队顺序并在下轮优先查询，避免固定顺序导致后排账号饥饿。失败保留卡片和额度，但全部费用显示“—”，不以窗口费用代替。

“价格”是购入人民币成本除以上述全部累计美元费用，显示 `¥0.2000/$`（例如 ¥20 ÷ $100）。成本未设置显示“未设置”，费用缺失或非正数显示“暂无计费”，零成本显示 `¥0.0000/$`，正价格低于四位小数阈值时显示 `<¥0.0001/$`。请求数保留原额度窗口统计，悬浮提示注明窗口，5h/7d 额度进度条独立于全部费用。
