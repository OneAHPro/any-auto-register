# ChatGPT 重登失败额度感知告警设计

## 目标

在现有 ChatGPT 自动鉴权、重登和 Codex2API 同步流程中，使用 Codex2API 返回的账号使用率过滤重登失败告警。额度已经用完的失败账号不参与告警；仍有额度的失败账号达到用户配置阈值时发送邮件，并在同一封邮件中汇总 Codex2API 全部正常可用账号的估算剩余额度，金额单位为美元。

## 用户可见规则

规则只保留两种有效情况：

1. 最终重登失败账号的有效使用率大于等于 100%：视为额度已经用完，剩余额度记为 `$0.00`，不计入告警阈值；此类账号数量再多也不触发邮件。
2. 最终重登失败账号的有效使用率小于 100%，且使用率和成本都是有效数字：视为仍有额度，计入告警阈值；数量达到现有配置阈值时发送邮件。

Codex2API 的额度重置时间不参与状态判断、金额计算或邮件展示。使用率或成本缺失、查询失败、非数字或不符合计算条件的账号，本轮不计入告警阈值，也不计入金额汇总。

现有配置键 `chatgpt_auto_relogin_alert_threshold` 和包含边界的触发方式保持不变。例如阈值为 5 时，符合第二种情况的失败账号达到 5 个即触发邮件。

## 剩余额度计算

对每个使用率小于 100%、使用率大于 0 且成本有效的账号独立计算：

```text
估算总额度 = 已用成本 / (使用率 / 100)
估算剩余额度 = 估算总额度 - 已用成本
             = 已用成本 * (100 - 使用率) / 使用率
```

例如账号使用率为 68%、已用成本为 `$81.42`：

```text
估算总额度 = 81.42 / 0.68 = $119.74
估算剩余额度 = 119.74 - 81.42 = $38.32
```

所有金额使用 Decimal 计算，在单账号展示和最终合计时统一四舍五入到小数点后两位。额度计算使用 Codex2API 的 `usage_percent_7d` 与 `billed_7d`；两者没有同时提供有效数值时跳过该账号。重置时间字段不读取。

## 告警统计口径

自动任务开始时取得一份 Codex2API 账号快照，并按本地账号 ID、远端账号 ID 或邮箱关联到本轮账号。最终重登失败时，根据同一份快照把账号分为：

- **仍有额度的失败账号**：使用率小于 100%，使用率与成本有效，参与告警阈值。
- **额度已用完的失败账号**：使用率大于等于 100%，不参与告警阈值。

明确删除、停用或封禁后被本地流程移除的账号，也使用移除前保存的快照完成同样判断，避免账号删除后丢失统计依据。

告警触发条件为：

```text
仍有额度的最终重登失败账号数 >= chatgpt_auto_relogin_alert_threshold
```

手工任务、停止任务和异常终止任务继续沿用现有抑制规则。每轮正常完成的自动任务最多发送一封告警邮件。

## 正常账号额度汇总

只有告警已经达到阈值时，才在邮件中生成 Codex2API 正常可用账号的额度汇总。正常可用账号需要同时满足：

- Codex2API 账号仍存在，且健康状态为正常；
- 7d 使用率为有效数字并小于 100%；
- 7d 成本为有效非负数字；
- 使用率大于 0，可按公式得到有效估算结果。

逐账号计算后汇总以下内容：

- 正常可用账号数量；
- 成功计算额度的账号数量；
- 全部正常可用账号的估算剩余额度合计；
- 逐账号邮箱、使用率、已用成本和估算剩余额度。

邮件只展示美元金额并使用 `$` 前缀，不进行人民币换算。邮件标题中的告警数量使用“仍有额度的最终重登失败账号数”。

## 数据流与代码改动范围

### Codex2API 健康探针

扩展 `services/chatgpt_codex2api_health.py` 的账号快照，使每个远端账号除现有健康状态外，还保留：

- `usage_percent_7d`
- `billed_7d`
- 用于账号关联的远端账号 ID 与邮箱

不读取或传递额度重置时间。探针仍复用现有 Codex2API 管理接口，不修改 Codex2API 服务。

### 自动任务

`api/tasks.py` 在记录最终重登失败或明确删除/封禁结果时，将对应的远端额度快照一并保存到本轮内存统计中。任务结束后生成：

- `quota_eligible_failure_count`
- `quota_exhausted_failure_count`
- `available_quota_accounts`
- `estimated_remaining_usd`

原始百分比、成本和估算结果只属于本轮任务，不写入账号密码、令牌或其他敏感字段。

### 邮件服务

`services/chatgpt_auto_relogin_alerts.py` 改为使用 `quota_eligible_failure_count` 判断阈值，并在纯文本和 HTML 邮件中增加额度汇总及逐账号明细。动态邮箱文本继续进行 HTML 转义。

## 场景示例

### 场景一：用完额度的失败账号很多

本轮有 30 个账号最终重登失败，它们的使用率全部为 100%。参与告警阈值的数量为 0，不发送邮件。

### 场景二：仍有额度的失败账号达到阈值

阈值为 5。本轮有 8 个账号最终重登失败，其中 3 个使用率为 100%，另外 5 个使用率分别为 68%、72%、45%、91% 和 37%，且百分比和成本都有效。参与阈值的数量为 5，发送一封告警邮件。

### 场景三：告警邮件汇总正常账号额度

告警触发时，Codex2API 有两个正常可用账号：

- 账号 A：53%，成本 `$68.26`，估算剩余 `$60.53`；
- 账号 B：68%，成本 `$81.42`，估算剩余 `$38.32`。

邮件展示的正常可用账号估算剩余额度合计为 `$98.85`。

## 测试策略

- 使用率 100% 和超过 100% 的最终失败账号不计入阈值。
- 使用率小于 100% 且成本有效的最终失败账号计入阈值。
- 额度已用完的失败账号超过阈值也不连接 SMTP。
- 仍有额度的失败账号恰好达到阈值时发送一封邮件。
- 使用率、成本缺失或非法时跳过该账号。
- 删除或封禁账号在本地移除后仍使用预先保存的快照判断。
- 单账号公式、美元两位小数和多账号合计结果正确。
- 邮件纯文本与 HTML 均包含正常账号总数、估算剩余额度合计和逐账号明细。
- 邮件不展示重置时间，不包含令牌、密码或管理密钥。
- 手工任务、停止任务、异常终止任务和 SMTP 失败行为保持回归通过。

## 部署与验收

1. 运行额度计算、健康探针、自动任务和邮件服务的聚焦测试，再运行现有后端回归测试。
2. 使用既有无停机部署流程更新服务器，不修改 Codex2API 容器。
3. 在服务器内只读调用 Codex2API 管理接口，核对 7d 百分比与成本字段。
4. 使用测试数据验证 100% 失败账号不触发、低于 100% 的失败账号达到阈值时触发，以及邮件美元汇总结果。
