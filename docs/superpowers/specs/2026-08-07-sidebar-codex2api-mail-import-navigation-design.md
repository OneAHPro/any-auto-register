# Codex2API 与邮箱导入主导航拆分设计

## 目标

把当前藏在“全局配置”内部的两个高频功能提升为主导航页面：

- `Codex2API`
- `邮箱导入`

两个入口显示在左侧主菜单的 `SMS接码池` 与 `全局配置` 之间。原有全局配置内部不再保留同名入口，避免用户面对两条到达相同功能的路径。

## 方案比较

### 采用：独立路由，复用现有配置状态

新增 `/codex2api` 和 `/mail-import` 路由，通过页面模式复用现有 `Settings` 的配置加载、保存、错误处理和敏感字段行为。页面只渲染对应内容，不显示全局配置的左侧标签栏。

优点是路由与导航语义清晰，现有业务逻辑只有一个来源，改动范围集中；缺点是 `Settings` 需要显式支持三种页面模式。

### 未采用：侧栏深链接到全局配置标签

侧栏可以跳转到 `/settings?tab=codex2api` 等地址，但视觉上仍属于全局配置，且容易出现侧栏和内部标签同时高亮。它没有完成真正的页面移动。

### 未采用：拆出全新的配置 Hook 和页面组件

彻底重构可以获得更纯粹的模块边界，但会同时触碰全局配置的加载、默认值、保存归一化和敏感字段处理，风险与本次导航目标不成比例。

## 路由与导航

主侧栏顺序调整为：

1. 仪表盘
2. 任务运行
3. 平台管理
4. 任务历史
5. 代理管理
6. SMS接码池
7. Codex2API
8. 邮箱导入
9. 全局配置

路由映射：

- `/codex2api` → Codex2API 独立设置页
- `/mail-import` → 邮箱导入独立页
- `/settings` → 其余全局配置

侧栏根据当前路径只高亮一个入口。折叠状态继续使用图标表达，不增加新的侧栏交互模式。

## 页面内容

### Codex2API

页面标题为 `Codex2API`，说明文字概括上传、删除联动、自动鉴权巡检和告警通知。保留当前全部内容：

- 管理面板与自动上传
- 删除联动
- ChatGPT 自动重登
- 邮件与 Bark 告警
- 现有加载、保存、测试按钮和错误提示

页面底部继续使用现有“保存配置”按钮。

### 邮箱导入

页面标题为 `邮箱导入`，说明文字明确支持 Outlook、Hotmail、MailAPI URL 与 iCloud 邮箱池。保留当前全部导入能力：

- 类型切换
- 邮箱裂变
- 文本导入与文件名设置
- 预览、单条删除和批量删除
- 导入后绑定默认邮箱来源
- 保存相关邮箱配置

“邮箱服务”标签继续保留默认邮箱服务和各提供商参数，但移除 `MailImportPanel` 操作面板。这样邮箱来源配置仍在全局配置中，实际导入管理集中到主导航页面。

## 状态与数据流

`Settings` 增加页面模式：

- `settings`：显示原有标签栏，但过滤 Codex2API，且邮箱服务不再嵌入导入面板。
- `codex2api`：固定渲染 Codex2API 配置与自动重登告警区域。
- `mail-import`：固定渲染邮箱导入面板。

三个模式共用同一个 `/api/config` 加载与保存流程。Bark 地址和其他敏感字段继续遵循现有不回显、空值保留策略。邮箱导入继续调用现有 `/api/mail-imports/*` 接口，不修改后端协议。

## 错误与加载状态

- 配置加载失败时，独立页面显示现有可访问错误提示与重试按钮。
- 保存进行中、成功和失败状态沿用现有交互。
- 邮箱导入提供商、预览、导入和删除错误沿用 `MailImportPanel` 当前提示。
- 页面模式不认识时回退到普通全局配置，不产生空白页。

## 测试

前端测试覆盖：

- 主侧栏存在两个新入口及对应路由。
- `/codex2api` 只显示 Codex2API 页面内容，不显示全局配置标签栏。
- `/mail-import` 显示邮箱导入面板及保存动作。
- `/settings` 不再显示 Codex2API 标签，也不再嵌入邮箱导入面板。
- 两个独立页面继续正确加载并保存现有配置。
- 既有 Bark、自动重登、删除联动和邮箱导入测试保持通过。

完成后运行前端全量测试、TypeScript/Vite 生产构建，并在生产切换前确认无运行中任务。部署使用不可变 release，保留当前 Bark release 和数据库备份作为回滚点。
