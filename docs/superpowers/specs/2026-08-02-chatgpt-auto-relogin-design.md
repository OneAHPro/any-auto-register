# ChatGPT 自动重登与 Codex2API 同步设计

## 目标

在单实例 Docker 部署中，每 30 分钟对全部具备重登凭据的本地 ChatGPT 账号执行一次真实重登，以并发 10 获取新的 Access Token / Refresh Token，并按账号身份覆盖同步到 Codex2API。

## 用户可见行为

- 设置入口位于“全局配置 → Codex2API”。
- 配置项包括启用开关、执行间隔（20–1440 分钟，默认 30）和并发数（1–10，默认 10）。
- 服务启动或首次启用后先等待一个完整间隔，不会立即触发整批重登。
- 自动任务使用现有任务日志面板展示，来源标记为“调度”，模式标记为“重登并同步”。
- 上一轮仍在运行、注册/接码任务正在运行或手工重登正在运行时，不叠加新的自动任务。
- 没有具备登录凭据的账号时进入“暂停—无可用账号”状态，不创建空任务；后续新增可登录账号后自动恢复计时。

## 架构

### 调度层

复用 `core.scheduler.Scheduler` 的单线程分钟级循环。调度器只调用自动化服务的轻量 `tick()`，不直接执行重登。`tick()` 从 SQLite 配置读取开关、间隔和并发，判断持久化的下次执行时间，并通过共享入队入口创建后台任务。

自动化状态（状态原因、上次任务、上次开始时间、下次执行时间）由服务维护并写入内部配置键；这些键不接受通用配置 API 写入。服务重启后读取状态，首次启用或从“无账号暂停”恢复时重新安排一个完整间隔。

### 任务层

从 `api.tasks` 抽取手工 API 与调度器共用的 `enqueue_chatgpt_relogin_task()`。自动任务使用 `source="schedule"`，并在元数据中写入 `mode="relogin"` 与 `automation=true`。现有批量执行、失败隔离、账号停用删除、令牌保存和 Codex2API 强制覆盖逻辑保持不变。

### 前台任务优先级

新增进程内 ChatGPT 任务协调器，符合当前单 Uvicorn worker、单容器部署模型：

1. 自动任务只在没有手工 ChatGPT 登录、注册、接码或重登任务时进入。
2. 手工任务到来时请求自动任务停止派发新账号。
3. 已在执行的自动账号在现有安全检查点退出；手工任务显示等待日志并在自动任务释放后开始。
4. 自动任务未处理的账号留到下一轮全量任务。
5. 多个手工任务仍可按现有并发模型运行；自动任务不会与它们重叠。

该协调器只负责进程内优先级，因此生产部署限定为一个应用副本和一个 Python worker。

## 可登录账号判定

自动任务查询全部 `platform="chatgpt"` 账号，并复用重登服务的凭据解析规则。密码/MFA 登录信息、邮箱登录上下文或 Outlook 导入凭据中至少一种完整可用时才进入任务。账号状态为 invalid 仍保留，因为真实重登可以修复失效状态；已删除账号不会进入查询。

## 冲突与故障处理

- 任务创建使用原子协调锁，避免调度器与手工请求同一时刻创建冲突任务。
- 到点时系统繁忙则记录“等待手工任务/上一轮”，每分钟复查；不会补发多轮积压任务。
- 单账号失败不阻塞整批；下一轮会再次尝试仍存在且可登录的账号。
- OpenAI 明确返回账号已停用或删除时，沿用现有逻辑删除本地账号。
- Codex2API 同步继续使用全局串行锁，避免按账号覆盖时凭据交叉。
- 自动任务不领取 SMS 接码池卡密；只有用户启动的新增邮箱接码任务会预留 SMS 卡密。

## API 与界面

- `GET /api/automations/chatgpt-relogin` 返回 enabled、state、reason、eligible_accounts、active_task_id、last_task_id、last_started_at、next_run_at、interval_minutes、concurrency。
- 通用 `GET/PUT /api/config` 增加三个白名单配置键。
- Codex2API 设置页新增独立自动化卡片，显示开关、间隔、并发、当前状态、可登录账号数、上次任务和下次执行时间。
- 任务运行页继续复用现有 `TaskLogPanel` 和 `RunningTasks`，不增加新的日志协议。

## 测试

- 后端单元测试覆盖首次启用延迟、30 分钟到期、繁忙跳过、无账号暂停、账号新增后恢复、重启恢复、配置边界和手工任务抢占。
- 任务 API 测试覆盖手工与自动共用入队入口、自动任务元数据及并发 10。
- 前端测试覆盖配置回显、保存 payload、20 分钟最小值、并发最大值 10 和暂停状态展示。
- 完整回归后构建 Docker 镜像，在持久化数据库副本上验证启动、状态 API、任务互斥和服务重启。

## 服务器基线

- 当前约 24 个账号的最低配置：4 vCPU、8 GB RAM、40 GB SSD、2 GB swap。
- 推荐长期配置：8 vCPU、16 GB RAM、60 GB SSD，Ubuntu 22.04/24.04 amd64，无需 GPU。
- 仅允许一个应用实例；SQLite 数据库与 `/runtime` 使用持久化卷。
- 管理 UI/API 只绑定本机并通过 Caddy/Nginx HTTPS 或 VPN 暴露；Solver 和辅助服务端口不开放公网。
- Docker 日志配置轮转，并对数据库卷定期备份。
