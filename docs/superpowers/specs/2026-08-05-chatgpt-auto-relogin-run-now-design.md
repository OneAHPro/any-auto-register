# ChatGPT 自动重登“立即执行”设计

## 目标

在 ChatGPT 账号列表顶部的“下次执行”倒计时右侧增加“立即执行”按钮。点击后立即创建一轮自动鉴权任务；本轮结束后，下一轮仍由自动调度器按“任务完成时间 + 当前配置间隔”计算。

本功能不修改自动重登开关、间隔、并发、告警阈值或 Codex2API 联动删除设置。

## 方案比较

1. **专用自动化触发接口（采用）**：增加 `POST /api/automations/chatgpt-relogin/run-now`，由自动重登状态机在同一把状态锁内完成资格查询、原子入队和状态持久化。任务带 `automation=true`，因此完成后的重新排期、告警与任务展示都复用现有自动化流程。
2. 复用手工重登接口：前端读取全部账号后调用 `/api/tasks/chatgpt-relogin`。这种任务不会被自动状态机完整接管，且前端分页无法可靠取得全部合格账号。
3. 把 `next_run_at` 改成当前时间等待调度器：实现简单，但调度器每 60 秒轮询一次，不能满足“立即执行”。

## 后端设计

`services/chatgpt_auto_relogin.py` 新增 `trigger_chatgpt_auto_relogin_now()`：

- 在 `_STATUS_TRANSITION_LOCK` 内读取一次完整配置快照。
- 自动重登关闭时拒绝触发，原因 `disabled_by_config`。
- 查询并排序当前所有合格账号；没有账号时写入 `paused_no_accounts` 并拒绝触发。
- 调用现有 `try_enqueue_scheduled_chatgpt_relogin()`。它继续负责手工任务优先、自动任务互斥和真正的自动任务创建。
- 成功后原子写入 `state=running`、`reason=task_running`、`active_task_id`、`last_task_id`、`last_started_at`，并清空 `next_run_at`。
- 入队繁忙或异常时不改写原倒计时，避免一次失败点击破坏原计划。
- 两次并发点击由状态锁串行化；第一轮成功后，第二轮会被任务门禁拒绝，不会创建重叠任务。

`api/automations.py` 新增 POST 路由：

- 成功返回 `200`：`accepted`、`task_id` 和最新 `status`。
- 自动重登关闭、没有合格账号或任务占用返回 `409`，并提供中文错误信息。
- 入队异常返回 `503`，保留原倒计时等待调度器重试。

任务完成后的重新计时不增加第二套逻辑。现有调度器观察到 `active_task_id` 已终止后，读取任务不可变的 `completed_at`，计算 `completed_at + interval`，保证计时起点是任务完成时刻而不是点击时刻或下一次调度器轮询时刻。

## 前端设计

`frontend/src/pages/Accounts.tsx` 在倒计时右侧渲染一个小尺寸“立即执行”按钮：

- 仅 ChatGPT 账号页显示。
- 状态尚未加载、自动重登关闭、当前轮运行中、正在停止或没有合格账号时禁用。
- 请求期间显示 loading，防止本浏览器重复提交。
- 成功后立即使用响应中的 `status` 更新页面，按钮进入禁用态，提示“自动化流程已立即启动”。
- 失败时展示服务端中文原因，随后由原有 5 秒轮询继续校准真实状态。

该按钮属于现有账号页顶部状态栏的单一操作，不新增组件或全局状态管理。

## 测试

后端覆盖：成功触发、完成后按完成时间重新排期、关闭状态、无账号、手工/自动任务占用、入队异常保留倒计时、并发点击只创建一轮、POST 路由状态码与响应结构。

前端覆盖：按钮紧跟倒计时、点击请求路径、成功 loading/状态更新、运行中与关闭时禁用、失败提示、非 ChatGPT 页面不显示。

上线后验证：保持生产配置原值，点击一次“立即执行”，确认只产生一个 `source=schedule` 自动任务；等待任务完成，核对 `next_run_at - completed_at` 等于配置的 10 分钟。
